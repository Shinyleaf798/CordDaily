做这个项目踩过的坑，按知识点排，不按时间。

跟 `DECISIONS.md` 的分工：那边记「这个项目为什么这么做」，会随决策被推翻而过时；这边记「我学会了什么」，讲的是平台行为和通用规律，不会过时。

## 1. 已经卸载的东西，没法做动画

**现象**

两次撞见同一件事：

- 页面关闭时，滑出去的是一块纯色面板，内容没了
- 底部弹层点关闭，直接消失，没有下滑动画

**原因**

动画要一帧一帧画，画的前提是那个东西**还在**。

- 原生栈：pop 的一瞬间路由就从 `state.routes` 里移除了，React 立刻卸载整棵子树，而原生层还在播关闭动画——滑走的必然是空壳
- 弹层：`{selectedId ? <Sheet/> : null}`，state 一变当场卸载，动画根本没机会播

**解法**

让决定权交给**能推迟卸载的那一方**。

- 换成 JS 栈：它把正在关闭的路由记在 `closingRouteKeys` 里，动画播完才真正移除
- 弹层写了个 `useSheetTransition`，`close()` 先播完出场动画，再调 `onDismiss`

**能带走的规矩**

> 要出场动画，就得有人负责「播完再卸载」。把这个职责放在能控制卸载时机的那一层。

## 2. 要等分，就别用百分比

**现象**

- 日历表头变成「日 一 二 三 四 五 / 六」——7 列排不下，第 7 个换行了
- 分类网格一行只有 4 个，明明写的是 5 个

**原因**

`1/7 = 14.2857…%`、`1/5 = 20%`，都可能除不尽。每格四舍五入到**整数像素**之后，7 格（或 5 格）加起来会**超过**容器宽度，最后一格就被挤到下一行。

在某些屏宽上正好，换台手机就崩——所以模拟器看着没事，真机上出问题。

**解法**

一行是一个真的 `<View style={{ flexDirection: 'row' }}>`，每格 `flex: 1`。

`flex` 分的是**剩余像素**，由系统保证加起来正好填满，不存在舍入溢出。

最后一行不足要补空格子，否则 `flex: 1` 会把剩下那两三个摊开占满整行。

**能带走的规矩**

> 等分用真的行 + `flex: 1`，不要用百分比 + `flexWrap`。

## 3. 圆角会被「伸出去的孩子」搞掉

**现象**

选中的分类格子在真机上画成**方块**。但二级面板里用的是**同一个样式**，却是圆的。

**原因**

`borderRadius` 的意思不是"把背景画成圆的"，而是：

> 把这个 View **连同里面的内容一起**裁成圆角。

我们那颗 `···` 点写的是 `right: -2, bottom: -2`——**故意骑在边界外面**。一裁就会被削掉一块。

系统于是放弃裁剪。**不裁 = 没有圆角**，背景退回矩形。

面板里的格子没有那颗点，所以一直是圆的。

**注意限定**：圆角 View **可以**装东西，图标待在里面完全没事。出问题的只有**越界**的那个。

**解法**

拆成两层，让「要圆角的」和「会溢出的」不是同一个 View：

```
iconSlot（方的，只当定位参照）
├─ circle（空的 View，圆角在这，里面什么都没有）
├─ icon
└─ childDot（溢出发生在这层，而这层本来就没圆角）
```

**能带走的规矩**

> 一个 View 要圆角，里面的东西就得待在圆里；有东西非要伸出去，就把圆角挪到另一个空 View 上。

**附：这个 bug 为什么查了很久**

它有三层伪装：

- 「存盘时是圆的，点一下别的分类就变方」→ 像是运行时出了问题。**其实形状从第一帧就是方的**，只是未选中时背景透明看不见；点击只改了一个颜色值，结构什么都没动
- 「面板圆、网格方」→ 像是两边样式分叉了。其实是**结构**不同（面板没有那颗点）
- 选中的恰好是 📚 🏠 这类本身就方的 emoji，一度以为看到的是 emoji 自己

**排查上的教训**：形状只跟**结构**有关，跟**状态**无关。一开始就该去比较两处的结构差异，而不是一直追问"点击时发生了什么"。

## 4. `toISOString()` 永远是 UTC

**现象**

凌晨记的账，在报销清单里显示成**前一天**。

**原因**

`toISOString()` 把时刻渲染成 UTC（结尾那个 `Z` 就是在说这件事）。东八区比 UTC 快 8 小时，所以**本地 00:00–08:00 这段时间里，UTC 还停在昨天**。

`iso.slice(0, 10)` 切出来的是「UTC 眼里的那一天」，不是你的。

而且**切完就救不回来了**：完整的 `2026-08-31T19:00:00.000Z` 里既有时刻也有基准，转到任何时区都行；切成 `2026-08-31` 之后，19:00 和 `Z` 都没了，而进不进位恰恰由那个 19:00 决定。

**解法**

要日期就问 `Date` 对象要，它的取值方法**本身就是按设备时区转换后再返回**的：

```ts
new Date(iso).getMonth()     // ✅ 本地的月
iso.slice(5, 7)              // ❌ UTC 的月
```

**能带走的规矩**

> ISO 字符串是给机器存的，`Date` 的取值方法是给人看的，中间那一步转换不能省。

补一句：**别手动加减时区偏移**（`d.getTime() + 8*3600*1000`）。夏令时地区会错，而 `getMonth()` 这类方法走的是完整的时区规则库，这些它都算得对。

## 5. 元素移走了，它原来的位置要有人画

**现象**

键盘弹出时输入块往上浮，浮上去之后**原来那块地方是一片黑**。

**原因**

之前为了让圆角跟着输入块走，把外层容器的底色去掉了。当时的假设是"反正上下两块加起来盖满了外壳，外壳画不画底色都看不见"。

这个假设**只在输入块不动的时候成立**。它一走，那块地方就没有任何一层在画东西，直接看穿到页面的黑底。

**解法**

外层补回底色，变成一张"垫底的纸"。它**不跟着动**，输入块走了它照画不误。

同时输入块**自己也要有底色**——它浮上去之后跑到了外层的范围之外，那里外层够不着。

两边各管一块、不重叠：

| 谁 | 负责画哪块 |
|---|---|
| 外层 | 输入块**原来**的位置 |
| 输入块 | 它**现在**在的位置 |

**能带走的规矩**

> 移动一个元素之前，先问：它走了之后，它原来占的那块地方由谁来画？

## 6. 「移到某个位置」≠「移动某段距离」

**现象**

想把输入块移到键盘上方，写了 `translateY(-keyboardHeight)`，结果它**冲过头了**，中间空出一大条。

**原因**

输入块本来就在面板顶部，离屏幕底边已经有半屏远。再往上抬一整个键盘的高度，自然远远超过键盘顶边。

「往上移一个键盘的高度」和「移到键盘顶边」，**只有当元素原本贴着屏幕底边时才等价**。

**解法**

算出真正需要补的那一截：

```ts
const restingGap = sheetHeight - noteFieldsHeight;   // 它本来离底边多远
const lift = Math.max(0, keyboardHeight - restingGap); // 只补不够的部分
```

差值 ≤ 0 就说明它本来就在键盘上方，**根本不用动**。

**能带走的规矩**

> 定位用"目标位置"表达，不要用"位移量"表达。位移量要先知道起点，而起点经常不是你以为的那个。

## 7. Android 的 edge-to-edge：窗口不再为键盘让位

**现象**

底部固定的面板被软键盘整个盖住，输入框看不见自己在打什么。

**原因**

`softwareKeyboardLayoutMode` 默认是 `resize`，按说窗口会自己缩上去。但 Expo SDK 54 之后 edge-to-edge 是强制开启的（`edgeToEdgeEnabled` 这个开关在 v57 的配置文档里已经不存在了），**窗口始终是整屏，键盘直接盖在内容上**。

**解法**

自己监听键盘高度，让需要避让的那一块主动让位：

```ts
Keyboard.addListener('keyboardDidShow', e => setHeight(e.endCoordinates.height))
```

平台差异：`keyboardWillShow` **只有 iOS 会发**，Android 只能用 `keyboardDidShow`。所以 iOS 上能跟键盘同步滑，Android 上是等键盘弹完再动。

**能带走的规矩**

> 全面屏 / edge-to-edge 下，"系统会自动帮我让开"这个假设不再成立，得自己处理。

## 8. 一个判断标准：这一层有没有自己的地址

不是踩坑，是这个项目里反复用到的一条判断规则，记下来。

弹层该开路由还是就地渲染？

1. **要把值交回给调用方吗？** 是 → 就地渲染（路由是单向的，拿不回值）
2. 否 → **它有自己的地址吗？**（能不能从别处直接跳进来 / 该不该出现在返回栈里 / 按返回键该退到哪）
   - 有 → 开路由
   - 没有 → 就地渲染

最能说明问题的一对：`set-budget`（路由）和分类编辑对话框（就地）——**长得一模一样、用的是同一个组件、都不回传值**，唯一的区别是前者有两个入口、能被直接跳进来。

> 外观和机制是两件事。「看起来像弹窗」不决定「它是不是一个页面」。
